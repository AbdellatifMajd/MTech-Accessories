-------------------------------------------------------------- about redux : 
# propsDrilling + stateManagement ==> that's why redux is presented: 
# separate the states in a store, instead of control that in our components. 
# the component send the action to the store, for it updates the state. 
# inside the store, there is a "reducer", wich is responsible for doing a comparison between the old state and the newest


As the application grows & becomes complex, it is hard to reproduce issues and add new features if you have 
no control over the state of your application.

Redux reduces the complexity of the code, by enforcing the restriction on how and when state update can happen.
